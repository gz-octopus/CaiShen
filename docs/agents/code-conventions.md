# 代码规范（agent 生成规则）

> 本文件是 CaiShen 仓库 agent 写代码时的强制约定。违反任一条即视为输出不合格。
> 与根目录 CLAUDE.md 的「关键约定」互补：本文件聚焦注释与命名，CLAUDE.md 聚焦日志/表格/CLI 模式。

## 注释规范（核心）

注释只回答两个问题，其他一律不写：

1. **是什么**：对象/字段/参数/返回值含义、单位、口径。
2. **为什么**：技术约束、已知坑、实测事实、设计依据（引用 ticket）、偏离惯例的原因。

**禁止**：

- **计划步骤式注释**——「第 N 步」「先…再…」「然后…」「下一步」「接下来」。代码本身表达执行顺序，注释不重复流程。
- **TODO 清单/待办注记**——需要做的事进 issue tracker（`gh issue create`），不进代码注释。
- **实现过程留痕**——「临时方案」「先这样」「调试用」不得出现在注释里；临时性代码要么修成正式形态，要么删除。
- **冗余复述**——注释不得逐行翻译代码（`# 遍历列表` 这种）。

**格式惯例**：

- 实测事实带日期与结论，如「2026-08-14 实测：p=1.0 时买入金额+成本超现金被拒绝」。
- 注释与代码同语言（中文），技术名词保留原文。
- 数字约束写清口径（如「百分点」「元/10股」），不写「较小/较大」这类模糊量词。

**正例**（strategy_research 现存代码）：

```python
# DATE 查询 end 边界为 exclusive（2.8.1 实测：end=08-13 得最后根 08-12），
# 内部 +1 天保证包含定稿区间末端交易日；end 为非交易日时 +1 天无副作用
```

**反例**：

```python
# 1. 先构建因子
# 2. 再构建信号
# 3. 然后创建系统，接下来跑回测（TODO: 后续改成多标的）
```

## 命名与结构

- 中文注释/文档，代码标识符英文；私有辅助用 `_` 前缀。
- 一次性实验脚本归 `test/t_*.py`；正式能力归功能包（如 `strategy_research/`），不混放。
- 生成物（数据/报告）必须 gitignore，代码仓库不存二进制产物。
